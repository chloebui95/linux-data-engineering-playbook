CPU & System Load — Deep Dive Reference

Diagnose high CPU utilization, runnable process queue length (load average vs CPU core count), and per-core bottleneck saturation.

⚡ Load Average Rule of Thumb
Load Average measures the number of processes waiting for CPU runtime or disk I/O. Always divide Load Average by total CPU core count (nproc). If Load / Cores > 1.0, tasks are queuing up!
⚡ Concept 1: Load Average Ratio (Load / Cores > 1.0 = Queuing)
Linux load average represents the average number of processes in Runnable (R) or Uninterruptible Disk Sleep (D) state.
• Golden Ratio Rule: Always divide load average numbers (1m, 5m, 15m) by total logical CPU core count (nproc).
• Thresholds: 0.7 * Cores = Optimal throughput; 1.0 * Cores = Fully saturated; > 1.0 * Cores = Tasks are queuing up waiting for CPU execution time or disk I/O completion.
📊 Concept 2: CPU % State Decomposition (%us, %sy, %wa, %hi, %si)
When diagnosing CPU spikes, top breakdown fields reveal the bottleneck nature:
• %us (User): User-space code execution (application logic, compute tasks).
• %sy (System): Kernel-space system calls, context switching, memory allocation.
• %wa (I/O Wait): CPU is idle waiting on disk or network storage I/O response.
• %si (Soft IRQ): Network packet processing handling. High %si indicates packet floods.

⚡ High CPU Load Spike & Server Lag

CPU & Load
🎯 Triage Strategy & Intention Logic:
• Load Trend vs Capacity: Compare 1m/5m/15m load average against logical core count (nproc). • Classify Bottleneck: Isolate %us (App code heavy), %sy (Kernel system call overhead), or %wa (Disk I/O wait).
Step 1: Quick Scan
uptime && nproc
Compare load average trend to available CPU logical core capacity
Step 2: Pinpoint Type
vmstat 1 5
Sample CPU metrics to isolate %us (App), %sy (Kernel), or %wa (Disk wait)
Step 3: Top CPU PID
top -b -n1 | head -n 15
Target process list by %CPU to find the top resource-consuming PID
Step 4: Remediation
kill -15 <PID>
Send SIGTERM (15) for graceful app shutdown or adjust priority with renice

🔥 High %wa (I/O Wait Saturation)

If top shows low %us (User) but high %wa (>20%), the CPU is idle waiting for slow disk storage. Jump to Disk Storage sub-page!

⚙️ Single-Thread CPU Bottleneck

Node.js or Python processes run single-threaded loops. Overall host CPU may show 12% on 8 cores, but Core 0 is 100% pinned! Check mpstat -P ALL.

>_ ps -eo pid,ppid,stat,cmd
Inspect process STAT execution states (R/S vs D uninterruptible disk sleep vs Z zombie)
$ ps -eo pid,ppid,stat,cmd | grep -E 'D|Z'
🔑 Process STAT Code Matrix
R / S Running / Interruptible Sleep (normal operating process)
D Uninterruptible Sleep — stuck waiting on disk I/O, NFS mount, or hardware lock
Z Zombie — terminated process whose parent failed to reap exit code with wait()
