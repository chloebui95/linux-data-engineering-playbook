Network & Ports — Deep Dive Reference

Comprehensive guide to socket bind IP verification (127.0.0.1 vs 0.0.0.0), port reachability probing, PID lookup, and host firewalls.

🛡️ The 3-Gate Network Security Chain (Every Gate Must Say YES!)
Gate ① Cloud SG ➔ STEP 1
Cloud Security Group
AWS SG / GCP Firewall (outside host VM). Must explicitly allow inbound port before packets can reach Linux kernel!
Gate ② Host OS Firewall ➔ STEP 2
Local Linux Firewall (UFW)
Kernel firewall filter. Must run sudo ufw allow 8080/tcp to open port in local netfilter tables.
Gate ③ App Socket Bind ➔ STEP 3
Process Socket IP Bind
App socket binding. Must listen on 0.0.0.0 (public interfaces), NOT 127.0.0.1 (localhost loopback only).

🌐 Concept 1: Socket Bind IPs (127.0.0.1 vs 0.0.0.0 vs Private IP)
Network applications bind to specific IP interfaces:
• 127.0.0.1:8080 (Localhost): Accepts connections ONLY from internal local processes. Remote clients receive "Connection Refused".
• 0.0.0.0:8080 (Any Interface): Accepts incoming connections on ALL network interfaces (eth0, docker0, loopback).
• Rule: Public web microservices must bind to 0.0.0.0!
🔌 Concept 2: TCP Socket States (ESTABLISHED, LISTEN, TIME_WAIT)
Kernel TCP socket lifecycle state tracking:
• LISTEN: Application is waiting for incoming client connections.
• ESTABLISHED: Active 3-way handshake completed; data is transferring.
• TIME_WAIT: Active close initiated; kernel waits 2x MSL (Maximum Segment Lifetime ~60s) before freeing socket tuple. High TIME_WAIT accumulation indicates connection pooling exhaustion.
🛡️ Concept 3: The 3-Gate Network Security Chain
Every incoming TCP request must pass through 3 independent security gates:
• Gate ① Cloud Security Group: Cloud provider network ACLs.
• Gate ② Host OS Firewall (UFW/iptables): Local kernel netfilter rules.
• Gate ③ App Socket Bind: Application listening on 0.0.0.0.
📁 System Paths & Config Files
/etc/hosts 🔥 High Debug Value

Static local IP-to-hostname mappings. Overrides external DNS name servers. Essential for database cluster alias configurations locally.

/etc/resolv.conf 🔥 High Debug Value

System DNS resolver configuration file. Defines nameserver IP addresses (e.g. nameserver 8.8.8.8) used for domain name lookups.

/etc/ssh/sshd_config ℹ️ System Reference

OpenSSH daemon configuration file. Controls SSH listening port (default 22), PasswordAuthentication settings, and PermitRootLogin security policies.

🔌 Connection Refused, Port Unreachable & DNS Failures

Network & Ports
🎯 Triage Strategy & Intention Logic:
• Bind & Handshake: Distinguish listening interface address (0.0.0.0 public vs 127.0.0.1 local loopback) and TCP handshake state. • Firewall & DNS Resolution: Test socket reachability (nc -zv), UFW drop policies, and nsswitch DNS resolution (getent hosts).
Step 1: Socket Bind
ss -tulpn | grep <port>
Verify service socket listener is bound to 0.0.0.0 (all interfaces) not 127.0.0.1
Step 2: Handshake Test
nc -zv <host> <port>
Test TCP handshake reachability (distinguish connection refused vs timeout drop)
Step 3: DNS Resolver
getent hosts <hostname>
Resolve hostname using system /etc/nsswitch.conf order (/etc/hosts -> DNS)
Step 4: Firewall Audit
sudo ufw status verbose
Audit host kernel packet filtering rules and allow incoming target TCP port

🚫 Localhost Only Bind (127.0.0.1:8080 Trap)

If ss -tulpn shows your FastAPI / Spark app bound to 127.0.0.1:8080, remote HTTP clients outside the VM will receive "Connection Refused". Update app configuration file to bind to 0.0.0.0:8080.

🛡️ Port State 'Filtered' (Nmap Probe)

When nmap -p 8080 returns filtered, a firewall (AWS Cloud SG or local OS UFW) is silently dropping connection packets without replying. Check Cloud SG rules and run sudo ufw status.

⚡ Test Remote Database Connectivity (nc -zv)

Run nc -zv 172.16.0.5 5432 to test direct TCP socket handshakes to a remote PostgreSQL host in 1 second without installing heavy database client tools.
