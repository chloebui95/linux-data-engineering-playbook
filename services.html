Services & Logs — Deep Dive Reference

Master real-time log streaming, systemd service lifecycle management, job scheduling (cron, at & timers), and process termination control.

⚙️ Signal Hygiene: SIGTERM (15) vs SIGKILL (9)
Always attempt kill -15 <pid> (SIGTERM) first! It allows applications to flush database buffers and release locks cleanly. Use kill -9 (SIGKILL) ONLY as an emergency un-catchable last resort!
⏰ Job Scheduling Architecture: at vs cron vs systemd timer
📌 at (One-Shot Task)
Runs a command ONCE at a future clock time (e.g. at now + 5 minutes). Queued & executed via atd daemon.
🔁 cron / crontab (Repeating Calendar)
Runs commands on a REPEATING calendar pattern (e.g. 0 5 * * * daily). Managed per user via crontab -e.
⏱️ systemd timer (OS Service Unit)
Triggers an OS-level .service unit on a schedule (systemctl list-timers). Available on cloud VMs (systemd PID 1).

>_ kill -15 vs kill -9
Terminate unresponsive processes gracefully (SIGTERM) or forcefully (SIGKILL)
$ kill -15 2211 || kill -9 2211
🔑 Flag Breakdown
-15 / SIGTERM Graceful termination signal (allows cleanup handlers & lock file deletion)
-9 / SIGKILL Immediate kernel termination signal (uncatchable, non-graceful)
🎯
LOCK FILE TRAP: kill -9 on Postgres or Spark master can leave stale lock files on disk requiring manual cleanup.

🎯
BACKGROUND SURVIVAL: Prevents Wi-Fi blips or closing laptop screen from killing multi-hour data pipelines!
📂 Standard File Descriptors (FD 0, 1, 2) & Redirection Rules
Every Linux process starts with 3 default communication channels. Child processes inherit parent file descriptors automatically.
FD Channel Name Default Target Redirection Syntax & Behavior
0 stdin Keyboard / Pipe < input.txt (Read input from file)
1 stdout Terminal Display > out.log (Overwrite) or >> out.log (Append)
2 stderr Terminal Display 2> err.log (Redirect error stream only)
1+2 2>&1 / /dev/null Combined Stream > log 2>&1 (Combine stdout+stderr into log) or > /dev/null 2>&1 (Silence all)
>_ Redirection Order & Process FD Inheritance
Understand why redirection sequence matters and how child subprocesses inherit file descriptors
$ spark-submit pipeline.py > pipeline.log 2>&1
🔑 Golden Redirection Rules
> file 2>&1 ✅ CORRECT SEQUENCE: Points stdout (1) to file, then points stderr (2) to wherever 1 points!
2>&1 > file ❌ WRONG SEQUENCE: Points stderr (2) to terminal first, then moves stdout (1) to file (stderr leaks to terminal)!
# Process Tree & FD Stream Inheritance: python script.py (> pipeline.log 2>&1) └── spark-submit (inherits stdout=pipeline.log, stderr=pipeline.log) └── java SparkDriver (inherits stdout=pipeline.log, stderr=pipeline.log)
🎯
SUBPROCESS INHERITANCE: When Python or Bash redirects > log 2>&1, all child processes launched by os.system or subprocess.Popen naturally stream stdout and stderr into that same log file without needing manual log forwarding code.
>_ set -euo pipefail
Strict Bash script safety header to fail fast on errors & undefined variables
#!/usr/bin/env bash set -euo pipefail
🔑 Flag Breakdown
-e Exit script immediately if any command returns a non-zero exit code
-u Treat unset / undefined variables as errors and exit immediately
-o pipefail Return exit status of last command in pipeline that failed
🎯
BASH SAFEGUARD: Prevents disastrous accidental commands like rm -rf / $UNSET_VAR from executing!
⚙️ Concept 1: Systemd Unit Management vs Legacy Cron & At
Linux daemon supervision and task automation architecture:
• Systemd (.service / .timer): PID 1 init system. Supervises processes, manages cgroups, logs stdout/stderr to journald, and auto-restarts failed services.
• Cron (crontab -e): Calendar-based task scheduler (5-field syntax: min hr dom mon dow). Runs periodic maintenance & backups.
• At (atd): One-shot future task queue (e.g. at now + 15 minutes).
🛑 Concept 2: Signal Hygiene (SIGTERM 15 vs SIGKILL 9)
Process termination signal discipline:
• SIGTERM (15): Catchable termination request. Allows process to flush buffers, release file locks, close database pools, and exit cleanly.
• SIGKILL (9): Immediate un-catchable kernel kill. Leaves corrupt database tables and lock files! Use ONLY when process ignores SIGTERM.
🐳 Concept 4: Docker Container Entrypoints, Here-Docs & Fail-Fast Automation
Production shell scripting for containerized ETL pipelines and orchestrators:
• Portable Shebang (#!/usr/bin/env bash): Ensures cross-distro portability across Ubuntu, Alpine, Debian, and RHEL base images.
• Here-Documents (cat << 'EOF' > config.json): Dynamically generates runtime JSON configs or DB schema updates inside container entrypoint scripts.
• Log Analysis Chains: Audit ETL error logs rapidly via grep -i 'error' /var/log/pipeline.log | cut -d' ' -f4 | sort | uniq -c | sort -nr | head -n 10.

⚙️ Systemd Unit Crash Loops & Start Failures

Services & Logs
🎯 Triage Strategy & Intention Logic:
• Host vs Container Daemons: Host VM daemons use systemctl/journalctl (PID 1 systemd). Containers use podman logs (PID 1 App). • Tracebacks & Reload: Fetch exception stacktraces from journal logs, verify script safeguards, and reload systemd unit definitions.
Step 1: Unit Status
systemctl status <svc> -l
Inspect daemon runtime state (active vs failed) and unit exit failure code
Step 2: Trace Logs
journalctl -u <svc> -e -n 100 -f
Fetch detailed exception tracebacks from host systemd logs or container logs
Step 3: Inspect Unit
systemctl cat <svc>
Verify ExecStart binary path, environment files, and script error safeguards
Step 4: Remediation
systemctl daemon-reload
Fix configuration file paths and reload systemd daemon definitions

🔄 Service In Start-Limit-Hit Crash Loop

If systemctl status shows "start-limit-hit", systemd stopped restarting the service after 5 rapid crashes. Fix underlying config error, then run sudo systemctl reset-failed.

💾 Missing Backup Retention Cleanup (100% Full Disk)

Creating daily database tarball backups with cron without a retention deletion line (find /var/backups -name "*.tar.gz" -mtime +7 -delete) will fill disk space to 100% within days! Always pair backup cron jobs with a 7-day purge rule.
